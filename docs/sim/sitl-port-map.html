Start order

  1. WSL: python3 tools/sitl/sim.py --bf-dir ~/betaflight
  2. Windows: node tools/sitl-serial-bridge.mjs --target 127.0.0.1:5761
  3. VS Code: run Ground: Debug (SITL)
  4. npm run dev --workspace @dronelink/air-webapp, open the ?fc= URL, pair, click Connect FC
  5. Desktop Configurator: Manual Selection, tcp://localhost:5771

Known traps

5761 is taken. The ground TCP bridge defaults to 5761 on all interfaces. Under mirrored networking that is the same port SITL's UART1 uses, so ground must run with BRIDGE_TCP_PORT=5771. The Ground: Debug (SITL) launch config sets it.
UART1 can come up dead. A Betaflight SITL startup race can drop a UART's server stream while the port still shows LISTEN. Connections open but MSP never answers, from WSL too. sim.py now probes UART1 after launch and relaunches SITL if it gets no reply.
Configurator must be the desktop build. The web version at app.betaflight.com, installed as a PWA or not, cannot open raw TCP. It treats every manual address as a WebSocket, so tcp://localhost:5771 fails with "Failed to connect to the selected port". Use the desktop (Tauri) build of Betaflight App.
Idle drop after 120 s. SITL closes a TCP client that has been silent for two minutes. If nothing polls the FC, the bridge link drops and the air webapp shows the FC as disconnected. Click Connect FC again.
